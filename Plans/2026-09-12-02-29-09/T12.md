# T12 ConfigStore, UTF-8, repair a atomická publikace

## Chronologie a konečný záměr

S01 §8 požaduje striktní validaci a atomický config. S03 D22, §5.1–5.6 a B03/B04 stanoví sedm availability stavů, 512 KiB včetně BOM, striktní UTF-8, pouze jeden úvodní BOM, revizi přes přesné bajty+identitu, repair pouze chybějící IP/klíč a last-successful-save-wins. Starý revision token není CAS. S04 zpřesňuje directory security error. S05 mění pouze startup pravidlo a ponechává bezpečnou publikaci. S06/S09 Contracts používá tutéž set-config cestu, žádný nový přímý zápis.

## Důkazy a klasifikace

Implementováno: `client/src/core/config/config_store.cpp` read/analyze/save/createDefault oddělují text, validní runtime a repair DOM. Failed fresh read zahodí starou cache. Token sdílí jen stejná identita a celý hash. save validuje vstup před mutexem/publikací, předalokuje receipt a nevyžaduje původní revizi. `client/src/core/config/config_document.cpp::normalizeConfigText` a validator provádějí limity, UTF-8 a single BOM. `client/src/platform/windows/config_files_win.cpp` má readBounded, CREATE_NEW staging/journal, flush skutečných handle, kontrolu identity a recoverLocked rozlišující confirmed/notPublished/unknown. Neznámý výsledek se nevydává za cancelled nebo jistý nezápis. Aktivní engine používá svůj přijatý snapshot, save jej nemění.

## Dopad na cílovou dokumentaci

client.md již má dostupnost, UTF-8, revize, repair a detailní atomický postup. Ponechat, od historických B03/B04 přesměrovat odkazy na vlastní nadpisy a existující testy. T02 doplní konkrétní validační meze. protocol.md beze změny, lokální config není wire. tray_UX.md ponechat skutečný editorový obsah a příznak unknown s odkazem na storage contract, ne kopii celého publikačního algoritmu. ACL politiku posuzuje zvlášť T13, tento záznam ji neprohlašuje automaticky shodnou se zdroji.

## Dopad na konstrukci testů

`test_config_store.cpp` pokrývá fresh read, exact bytes/identity, last-save-wins, souběžné celé save, no overwrite create, single BOM a chyby. `test_config_files_win.cpp` pokrývá limit, reparse, připnuté identity, fault injection write/flush/publication, crash boundaries, confirmed receipt po external change, unrelated target unknown a create race. Pokrytí hlavních invariantů je rozsáhlé. Nový redundantní test kvůli dokumentační konsolidaci není nutný. Samostatná testovací práce musí pouze zajistit, že NTFS scénáře skutečně proběhly s vhodným tokenem a případný NOT RUN zůstane viditelný. Riziko ztráty nebo záměny configu ospravedlňuje existující integrační/fault testy. V této fázi žádné testy neběžely.

Stav: uzavřeno.
