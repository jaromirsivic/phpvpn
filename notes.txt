# Návrh PHP VPN serveru a klientů

- Vytvořit nový VPN server běžící v jediném souboru `phpvpn.php`.
- Celý server, tedy jeden phpvpn.php soubor, budou volat desítky klientů a každý klient v něm bude udržovat minimálně dvě dlouhá několik sekund streamovaná spojení
- Funkcionality serveru implementovat jako fault-proof a concurency-safe. **TOTO JE ABSOLUTNÍ NUTNOST!**
- Kód musí být čitelný a performance musí být skvělá. **MAXIMÁLNĚ SE ZAMĚŘ NA PERFORMANCE A SECURITY**
- Při otevření jeho URL ve webovém prohlížeči se zobrazí velmi jednoduchá stránka s textem h1 `Server is running`.
- Server bude mít jen několik REST API endpointů a všechny budou přijímat pouze metodu POST.
- Endpoint `health` vrátí JSON s položkami `status` (typicky `OK`) a `serverTime`. Čas bude ve formátu `YYYY-MM-DD HH:MM:SS`.
- Další endpointy budou `push` a `pull`.

## Konfigurace VPN klienta

- VPN klient je virtuální síťový adaptér / virtuální síťová karta s VPN ovladačem, určený například pro Windows.
- Klient poběží v oznamovací oblasti systému (tray) a uživatel si jej nainstaluje na svůj počítač; více uživatelů instaluje stejný typ klienta na své počítače.
- `push` bude používat tento virtuální adaptér pro komunikaci se serverem.
- Nastavení každého klienta obsahuje:
  - URL serveru, tedy cestu k jedinému běžícímu PHP souboru;
  - SERVER_SECRET
  - lokální VPN IP adresu klienta např. 10.99.99.4;
  - access token pro danou ip adresu;
  - pole communication contracts, kde jsou uvedeny hesla pro zašifrování IP packetu, když klient komunikuje s jiným klientem. Jako šifra se bude používat AES-256.
- VPN síť používá adresy z rozsahu `10.99.99.2` až `10.99.99.254`; příklad klientské adresy je `10.99.99.14`.
- Access token je 256bitový token, typicky zapsaný hexadecimálně.
- Communication contract představuje heslo/sdílený klíč pro každou dvojici klientů (například počítač 1 a počítač 2). Jde typicky o 256bitový klíč používaný symetrickou šifrou AES-256.

Příklad configuračního json souboru:

```json
{
  "serverUrl": "https://example.com/phpvpn.php",
  "serverSecret": "REPLACE_WITH_A_RANDOM_SECRET",
  "virtualIp": "10.99.99.4",
  "accessToken": "0404040404040404040404040404040404040404040404040404040404040404",
  "bilateralCommunicationContracts": {
    "10.99.99.2": "AES_256_SHARED_KEY_FOR_10.99.99.2",
    "10.99.99.3": "AES_256_SHARED_KEY_FOR_10.99.99.3"
  }
}
```

## Struktura souboru `phpvpn.php`

- Při běžném otevření přes prohlížeč soubor vrátí jednoduchou HTML stránku se stavem serveru, například h1 `Server is running`.
- Pozor pokud není nastaven SERVER_SECRET na alespoň 16 znaků, tak výchozí stránka vrátí pod úvodním h1 `Server is running` červený text `SERVER_SECRET is not configured correctly. This is a security risk. The secret must be at least 16 characters long and generated randomly using alphanumeric characters. Please open phpvpn.php in a text editor and update SERVER_SECRET.`
- V horní části souboru bude konfigurační blok; jde prakticky o jedinou část, kterou bude uživatel upravovat.
- Pořadí konfiguračních parametrů:
  1. `SERVER_SECRET` — výchozí hodnota je prázdná.
  2. `BUFFER_TIMEOUT` — výchozí hodnota 250 ms.
  3. `CONNECTION_TIMEOUT` — výchozí hodnota 15 000 ms (15 sekund).
  4. `ACCESS_TOKENS` — seznam dvojic IP adresa a access token.
- `access_tokens` bude obsahovat položky pro všechny VPN adresy `10.99.99.2` až `10.99.99.254`.
- Každá položka bude jednoduchá dvojice (tuple): IP adresa a odpovídající access token.
- Výchozí token se vytvoří opakováním hexadecimálního zápisu posledního čísla IPv4 adresy tak, aby vyplnil 256 bitů. Příklad: pro `10.99.99.2` je poslední číslo 2, což je hexadecimálně 02 a proto se opakuje `02` 32 krát, pro `10.99.99.3` se opakuje `03` 32 krát.

## Doplnění konfigurace a endpointů

- Pod timeouty doplnit parametr `BUFFER_SIZE` s výchozí hodnotou 256 KB.
- Doplnit parametr `MAX_BUFFERS` s výchozí hodnotou 128; určuje maximální počet bufferů zapsaných do cílového adresáře před garbage collection.
- Endpoint `/health` bude dostupný přes GET i POST. Vrátí stav `OK` a aktuální čas serveru.
- Endpoint `push`: virtuální síťový adaptér naváže spojení se serverem a v HTTP hlavičce předá bearer token. Server bearer token převezme a ověří.
- Bearer token se vypočítá jako `sha256(SERVER_SECRET . ACCESS_TOKEN[virtual_ip_address] . DATETIME_NOW_IN_FORMAT(yyyy-mm-dd-hh-MM))`.
- Vstup hashe spojuje serverový secret, access token daného klienta a aktuální serverový čas zaokrouhlený na minutu.

## Ověření bearer tokenu a průběh endpointu `push`

- Cílem je z bearer tokenu zjistit jaká IP adresa navazuje komunikaci a jestli je oprávněná komunikaci navázat
- PHP server tedy soubor phpvpn.php při navázání push, ale i pull komunikace vytvoří mapu access tokenů pro všechny klientské IP adresy. Tedy pro adresy 10.99.99.2 až 10.99.99.254
- Pro každý access token vypočítá SHA-256 bearer token pro aktuální minutu a taky pro předchozí minutu.
- Každé klientské IP adrese proto v danou chvíli odpovídají dva platné bearer tokeny. Překrytí řeší případ, kdy klient získá čas těsně před změnou minuty.
- Server podle přijatého bearer tokenu dohledá a určí klientskou IP adresu, ke které token patří. Toto přiřazení je zásadní pro další zpracování spojení.
- Před voláním `push` klient zavolá `/health`, získá aktuální čas serveru, oseká ho na minutu a podle stanoveného vzorce vypočítá bearer token.
- Klient zavolá `push` a předá token v HTTP hlavičce `Authorization: Bearer ...`.
- Po ověření tokenu server po dobu `connection_timeout` (výchozích 15 sekund) přijímá od daného klienta stream dat.
- Stream tvoří sekvence JSON zpráv obsahujících serializované IP pakety.

### Formát zprávy s IP paketem

```json
{"type": "data", "uuid": "UUID", "src": "10.99.99.2", "dst": "10.99.99.4", "data": "ENCRYPTED_IP_PACKET_DATA_IN_BASE64"}
```

- `type` určuje druh zprávy, pro paket má hodnotu `data`.
- `uuid` je identifikátor zprávy/paketu ve formátu UUID.
- `src` je zdrojová VPN IP adresa která musí odpovídat zjištěné ip adrese z bearer tokenu
- `dst` cílová VPN IP adresa.
- `data` obsahuje šifrovaná data IP paketu.
- Každý JSON objekt se odesílá inline a kompaktně: bez odsazení, formátovacích nových řádků a pokud možno bez zbytečných mezer.
- Jednotlivé pakety ve streamu odděluje jeden znak nového řádku (`\n`); uvnitř jednotlivého JSON objektu se žádný nový řádek nevyskytuje.

## Zpracování streamu endpointu `push`

- Po úspěšném navázání a ověření spojení `push` server provede garbage collection pouze adresáře IP adresy klienta, který spojení navázal.
- Po otevření komunikačního kanálu klient kontinuálně posílá jednotlivé IP pakety přes otevřené spojení `push`.
- Server příchozí data průběžně bufferuje. Po přijetí znaku nového řádku vyjme jeden kompletní JSON paket a rozparsuje jej.
- Pro každý paket server ověří:
  - `type` má hodnotu `data`;
  - `src` odpovídá klientské IP adrese určené z bearer tokenu;
  - `dst` patří do rozsahu `10.99.99.1` až `10.99.99.255`.
- Pokud kterákoli kontrola selže, server spojení okamžitě ukončí a vrátí HTTP `401 Unauthorized`.

## Bufferování a ukládání autorizovaných paketů

- Platný paket má `type: data`, `src` odpovídající IP určené z bearer tokenu, cílovou adresu v povoleném rozsahu a v položce `data` celý zašifrovaný IP paket v Base64, který není nutné zpracovávat, protože server nezná šifru, která by ho dokázala rozšifrovat.
- Server drží v paměti samostatné buffery pro cílové klienty v rozsahu `10.99.99.1` až `10.99.99.255` a zařazuje/ukládá do nich přijaté serializované pakety.
- Po uplynutí `BUFFER_TIMEOUT_MS` (výchozích 250 ms; přesnost intervalu nemusí být absolutní) zpracuje pouze neprázdné buffery.
- Pro každý neprázdný buffer zajistí cílový adresář relativně k `phpvpn.php` ve struktuře `phpvpn/10_99_99_0/NNN/`, kde `NNN` je poslední oktet cílové IP ve tříznakovém tvaru s úvodními nulami, například `004` pro `10.99.99.4`.
- Pokud potřebná adresářová struktura neexistuje, server ji vytvoří dynamicky. Pokud se adresářovou strukturu nepodaří vytvořit server ukončí spojení s klientem a vrátí kód 404 s json souborem popisujícím chybu např. {"status": "error", "description": "Cannot create directory phpvpn/10_99_99_0/004"}
- Obsah bufferu se nejprve uloží do souboru s příponou `.writing`, například ve formátu `YYYY-MM-DD-HH-MM-SS-FFF_UUID.writing`; čas obsahuje milisekundy a UUID se vytvoří za běhu.
- Před přejmenováním `.writing` na `.data` server v cílovém adresáři spočítá existující soubory `.data`.
- Pokud je jejich počet alespoň `MAX_BUFFERS`, server nad tímto cílovým adresářem provede garbage collection a počet souborů `.data` zkontroluje znovu.
- Pokud počet souborů `.data` ani po garbage collection není menší než `MAX_BUFFERS`, server připravený soubor `.writing` smaže a na `.data` jej nepřejmenuje.
- Jinak se soubor po úspěšném zápisu přejmenuje na stejný název s příponou `.data`.
- Po průchodu všemi buffery server buffery vyčistí.
- Pokud velikost kteréhokoli paměťového bufferu překročí konfigurační konstantu `BUFFER_SIZE_KB` byť o jediný bajt, server nečeká na `BUFFER_TIMEOUT_MS`. Okamžitě zapíše a vyčistí všechny aktuálně neprázdné buffery, poté pokračuje s novými prázdnými buffery.
- Poté ověří, zda neuplynul `CONNECTION_TIMEOUT_MS` (výchozích 15 sekund). Pokud ne, pokračuje v příjmu streamu a dalším bufferování s prázdnými buffery.

## Endpoint `pull` (v diktátu označovaný také jako „pool“)

- Klient udržuje dvě dlouhá spojení: `push` pro odesílání serializovaných IPv4 paketů a `pull` pro příjem paketů ze serveru.
- Spojení `push` trvá maximálně `CONNECTION_TIMEOUT_MS` (výchozích 15 sekund), poté se uzavře a klient jej znovu otevře. Stejný princip dlouhého spojení používá i `pull`.
- Klient při volání `pull` předá bearer token. Server jej ověří, určí klientskou IP adresu a otevře odpovídající cílový adresář, například pro `10.99.99.4` adresář `phpvpn/10_99_99_0/004/`.
- Server v tomto adresáři během aktivního čekání periodicky vyhledává soubory s příponou `.data` a streamuje jejich obsah klientovi.
- Nalezené soubory `.data` se seřadí podle názvu, takže se nejdříve odešlou nejdříve vytvořené soubory.
- Každý soubor server otevře, zapíše jeho obsah do odpovědi a po úspěšném odeslání jej smaže.
- Pokud nejsou ve složce žádné soubory program aktivně čeká BUFFER_TIMEOUT a pak se pokusí vyhledat soubory znovu
- Při ukončení `pull`/`pool` spojení server provede garbage collection pouze adresáře IP adresy klienta, který spojení navázal: smaže soubory starší než jedna minuta, protože už nebyly odeslány včas. Týká se to jen souborů s příponou .data a souborů s příponou .writing. Pokud se nějaký soubor nedaří smazat, tak se pokusí jej přejmenovat na .error
- Garbage collection se neprovádí nad adresáři jiných IP adres.
- Garbage collection je třeba implementovat univerzálně aby jej mohl na adresáři dané IP adresy volat push i pull.
