# Formální zadání: automatické vytvoření konfigurace a trvalé volby Configuration Wizardu

## Shrnutí

Windows Service phpvpn musí při každém svém startu ověřit, zda v autoritativním umístění existuje `config.json`. Pokud soubor neexistuje, služba automaticky a atomicky vytvoří výchozí konfiguraci. Použije přesně stejnou sdílenou šablonu, jakou načítá funkce Reset v okně Edit Config, rozšířenou o tři nové volitelné booleovské členy pro stav Configuration Wizardu.

Existující `config.json` se při startu nesmí měnit ani přepisovat. To platí i pro existující neplatný, nečitelný nebo jinak problematický soubor.

Nové členy uchovávají volby `Use default SERVER_SECRET`, `Use default access key` a `Automatically detect IP address`. Jejich názvy obsahují příponu `InWizard`, aby bylo přímo v JSONu zřejmé, že je používá pouze Configuration Wizard. Běžný VPN provoz služby podle nich nesmí měnit svou konfiguraci, kryptografii ani směrování. Nevznikne žádný konfigurační člen pro vytváření výchozích communication contracts. Checkbox pro doplnění chybějících výchozích kontraktů však bude vždy viditelný v posledním kroku Wizardu, a to i při editaci existující konfigurace.

## Projektový kontext

- Konfiguraci a její chráněné umístění vlastní Windows Service. Tray aplikace nesmí zapisovat `config.json` přímo.
- Projekt již používá jednu sdílenou výchozí šablonu pro Reset v Edit Configu a pro službovou operaci vytvoření výchozí konfigurace.
- `ConfigStore` již podporuje publikaci v režimu `createIfMissing`, který nesmí přepsat soubor vzniklý souběžně.
- Současná normativní dokumentace naopak výslovně říká, že instalace ani start služby konfiguraci nevytvářejí. Toto pravidlo je tímto zadáním nahrazeno.
- Configuration Wizard nyní odvozuje stav checkboxu pro `SERVER_SECRET` porovnáním hodnoty a stav checkboxu pro Access Key podle přítomnosti klíče. Nové členy mají původ volby uchovat explicitně.

## Požadovaná struktura konfigurace

Do objektu `masterSetup` přidat tyto tři volitelné členy v existujícím stylu camelCase:

```json
{
  "masterSetup": {
    "serverUrl": "http://127.0.0.1/phpvpn.php",
    "trustAnyTlsCertificate": true,
    "serverSecret": "CHANGE_THIS_SERVER_SECRET",
    "useDefaultServerSecretInWizard": true,
    "vpnCidr": "10.99.99.0/24",
    "virtualIp": "10.99.99.2",
    "autoDetectIpAddressInWizard": true,
    "accessKey": "0202020202020202020202020202020202020202020202020202020202020202",
    "useDefaultAccessKeyInWizard": true
  },
  "communicationContracts": {
    "10.99.99.3": {
      "payloadKey": "918c488528c2bc41a90f000b0a63bab0ba418790058ea7b448a3760aec16349d"
    }
  }
}
```

Výchozí dokument musí jinak zůstat totožný s aktuální šablonou Edit Config Resetu. Včetně současných hodnot, struktury a výchozího communication contractu.

## Funkční požadavky

### 1. Automatické vytvoření při startu služby

1. Při každém startu služby nejprve připravit a obnovit chráněné konfigurační úložiště podle stávajících pravidel.
2. Poté jednorázově zkontrolovat autoritativní cestu ke `config.json`.
3. Pokud soubor skutečně neexistuje, vytvořit jej z jediné sdílené výchozí šablony.
4. Publikace musí použít stávající bezpečný a atomický režim `createIfMissing`.
5. Pokud soubor existuje, jeho obsah i bajty musí zůstat beze změny. Služba nesmí při startu doplňovat nové členy do starší konfigurace ani opravovat její obsah.
6. Pokud mezi kontrolou a publikací soubor vytvoří jiný proces, služba jej nesmí přepsat.
7. Instalátor nemá vytvářet druhou kopii šablony. První vytvoření po instalaci zajistí start služby stejným mechanismem jako každý pozdější start.
8. Chyba vytvoření nesmí vést k částečnému nebo poškozenému cílovému souboru. Služba zůstane dostupná pro IPC a diagnostiku, VPN provoz však bez platné konfigurace zůstane fail-closed.

### 2. Nové volitelné členy a kompatibilita

1. Striktní validátor musí nové členy přijmout pouze jako JSON boolean. Jiný typ je chyba konfigurace.
2. Všechny tři členy jsou volitelné, aby zůstaly platné starší konfigurace.
3. Výchozí šablona musí všechny tři členy obsahovat s hodnotou `true`.
4. Pokud člen ve starší konfiguraci chybí, zachovat dosavadní chování:
   - `useDefaultServerSecretInWizard` se odvodí jako `true` pouze při přesné shodě `serverSecret` s `CHANGE_THIS_SERVER_SECRET`.
   - `useDefaultAccessKeyInWizard` se odvodí jako `false`, pokud existuje platný uložený `accessKey`. V repair režimu bez klíče se odvodí jako `true`.
   - `autoDetectIpAddressInWizard` se odvodí jako `false`, pokud existuje platná uložená `virtualIp`. V repair režimu bez IP se odvodí jako `true`.
5. Tyto členy jsou výhradně metadatovým stavem Configuration Wizardu. Běžný VPN runtime je smí pouze tolerovat při načtení dokumentu. Nesmí je používat k výběru efektivního secretu, IP adresy, Access Key, kryptografie ani směrování. Pro běžný VPN provoz jsou nadále autoritativní konkrétní hodnoty `serverSecret`, `virtualIp` a `accessKey` uložené v dokumentu.

### 3. Krok 2 Configuration Wizardu

1. Checkbox `Use default SERVER_SECRET` se při otevření inicializuje z `useDefaultServerSecretInWizard`, pokud je člen přítomen.
2. Při hodnotě `true` musí být checkbox zaškrtnutý, pole secretu zakázané a zobrazená hodnota musí být `CHANGE_THIS_SERVER_SECRET`.
3. Při hodnotě `false` musí být checkbox odškrtnutý a pole editovatelné s uloženou hodnotou `serverSecret`.
4. Změna checkboxu musí změnit rozpracovanou hodnotu `useDefaultServerSecretInWizard`.
5. Finish uloží jak výsledný `serverSecret`, tak odpovídající `useDefaultServerSecretInWizard`.

### 4. Krok 3 Configuration Wizardu

1. Checkbox `Use default access key` se inicializuje z `useDefaultAccessKeyInWizard`, pokud je člen přítomen.
2. Při hodnotě `true` se použije výchozí Access Key odvozený stávajícím algoritmem z aktuální IP adresy. Pole Access Key je zakázané a při změně IP se klíč znovu přepočítá.
3. Při hodnotě `false` zůstane uložený Access Key uživatelsky editovatelný.
4. Krok dostane checkbox `Automatically detect IP address`, jehož stav se inicializuje z `autoDetectIpAddressInWizard`.
5. Při hodnotě `true` se po úspěšném získání ověřených serverových informací použije stávající algoritmus návrhu IP adresy. Automaticky navržená IP nahradí i statickou placeholder hodnotu z výchozí konfigurace.
6. Při hodnotě `false` se zachová uložená `virtualIp` a uživatel ji může ručně upravit.
7. Při automatickém režimu má být pole IP zakázané. Pokud návrh nelze získat, UI zobrazí konkrétní chybu a dovolí automatický režim vypnout a zadat IP ručně.
8. Finish uloží výsledné `virtualIp`, `accessKey`, `autoDetectIpAddressInWizard` a `useDefaultAccessKeyInWizard`.

### 5. Communication contracts

1. Do `config.json` nepřidávat člen typu `createDefaultCommunicationContracts`, `useDefaultCommunicationContracts` ani jeho ekvivalent.
2. Poslední krok vždy zobrazí checkbox pro vytvoření chybějících výchozích communication contracts. Checkbox musí být viditelný v režimech create, reset, edit i repair bez ohledu na to, zda konfigurace při otevření Wizardu existovala a kolik již obsahovala kontraktů.
3. Checkbox bude při každém novém otevření Wizardu výchozím stavem zaškrtnutý. To platí při nulovém, částečném i úplném počtu existujících výchozích kontraktů. Jeho stav se do `config.json` neukládá.
4. Poslední krok vedle checkboxu zobrazí počet již existujících kontraktů a počet výchozích kontraktů, které při Finish zbývá doplnit.
5. Pokud checkbox zůstane zaškrtnutý, Finish projde výchozí kandidátní adresy s posledním oktetem 2 až 15, vynechá vlastní `virtualIp` a vytvoří pouze dosud chybějící peer položky.
6. Každý již existující communication contract se zachová včetně původního `payloadKey`. Výchozí generování jej nesmí přepsat, přegenerovat ani odstranit.
7. Pro nově doplněný peer se `payloadKey` vytvoří současným algoritmem SHA-256 nad kanonicky seřazenou dvojicí vlastní a peer IP oddělenou jedním podtržítkem.
8. Pokud žádný kontrakt nechybí, zaškrtnutý checkbox je bezpečná no-op operace. Finish nesmí jen kvůli tomu selhat ani měnit existující kontrakty.
9. Pokud uživatel checkbox odškrtne, Finish žádné výchozí kontrakty nepřidá a existující kontrakty zachová.
10. Automaticky vytvořený startovní dokument obsahuje stejný výchozí contract jako šablona Resetu v Edit Configu. Proto při prvním otevření Wizardu nebude seznam prázdný, přesto checkbox zůstane zaškrtnutý a Finish doplní zbývající kontrakty.
11. Výchozí generování je podporované pro současný podporovaný tvar `10.A.B.0/24`. U jiného platného CIDR zůstane checkbox viditelný, ale bude zakázaný s vysvětlením, že pro tento adresní prostor nelze výchozí sadu vytvořit.

## Konzistence ukládání

- Edit Config Reset, službové automatické vytvoření při startu a případná existující operace vytvoření výchozí konfigurace musí číst jednu společnou šablonu. Nesmějí vzniknout tři nezávislé JSON konstanty.
- Edit Config musí nové členy zobrazit a uložit jako běžnou součást dokumentu.
- Configuration Wizard v edit/repair režimu musí při Finish rozšířit nynější patch čtyř hodnot tak, aby vedle konkrétních hodnot uložil také tři nové příznaky. Při zaškrtnuté volbě kontraktů navíc aditivně doplní chybějící výchozí peer položky. Ostatní neprezentované členy dokumentu musí zachovat.
- Reset Wizardu i Reset v Edit Configu musí používat nové výchozí hodnoty všech tří příznaků.
- Automatické vytvoření při startu nesmí procházet tray IPC. Jde o interní operaci služby nad stejným `ConfigStore` a stejnými bezpečnostními pravidly publikace.

## Akceptační kritéria

1. Po prvním startu nově nainstalované služby existuje validní `config.json`, pokud před startem neexistoval.
2. Vytvořený soubor se obsahově rovná aktuální šabloně Edit Config Resetu a obsahuje všechny tři nové členy s hodnotou `true`.
3. Druhý a každý další start služby ponechá existující `config.json` bajtově beze změny.
4. Existující neplatný nebo nečitelný soubor se při startu nenahradí výchozí šablonou.
5. Souběžně vzniklý soubor není automatickým vytvořením přepsán.
6. Starý validní dokument bez nových členů zůstane validní a Wizard použije výše definované kompatibilní odvození stavů.
7. Nový dokument odmítne neboolean hodnotu kteréhokoli ze tří příznaků.
8. Krok 2 načte, mění a po Finish zachová `useDefaultServerSecretInWizard` společně s odpovídajícím secretem.
9. Krok 3 načte, mění a po Finish zachová `useDefaultAccessKeyInWizard` a `autoDetectIpAddressInWizard` společně s odpovídající IP a Access Key.
10. Při `autoDetectIpAddressInWizard=true` nahradí ověřený návrh IP placeholder z výchozí konfigurace. Při hodnotě `false` zůstane uložená IP zachovaná.
11. V konfiguračním schématu nevznikne žádný nový příznak pro výchozí communication contracts.
12. Automatické vytvoření používá chráněný atomický zápis služby a při chybě nezanechá částečný cílový soubor.
13. Testy pro Edit Config Reset, automatické vytvoření a službovou výchozí šablonu ověřují jediný shodný dokument, aby se jejich obsah nemohl časem rozejít.
14. Checkbox pro doplnění kontraktů je viditelný a výchozím stavem zaškrtnutý také při editaci existující konfigurace s nulovým, částečným nebo úplným počtem kontraktů.
15. Finish se zaškrtnutým checkboxem zachová všechny existující kontrakty a doplní pouze chybějící peer adresy z výchozí kandidátní sady, kromě vlastní IP.
16. Opakovaný Finish nebo nové spuštění Wizardu nad již úplnou sadou kontraktů je idempotentní z hlediska obsahu `communicationContracts`.
17. Odškrtnutý checkbox ponechá `communicationContracts` obsahově beze změny.

## Implementační vodítka

Následující body jsou odvozené z aktuální architektury, nikoli nová uživatelská omezení:

- Nejmenší bezpečná změna je zavolat po obnově úložiště existující `ConfigStore::createDefault()` a zachovat jeho `createIfMissing` semantiku.
- Přidružený dokumentový model musí nést tři nové booleovské hodnoty až do `WizardView`. Je vhodné je oddělit od runtime části `ClientConfig`, aby je běžný VPN runtime vůbec nekonzumoval.
- Odpověď `wizard-open` musí stav příznaků dopravit do tray modelu. Je vhodné rozšířit strukturu Wizard fields nebo přidat jednoznačně pojmenovaný prezentační blok, přičemž IPC validace musí zůstat uzavřená a striktní.
- Při `autoDetectIpAddressInWizard=true` musí `WizardModel` přijmout `suggestedIp` z úspěšného kroku secret i v případě, že výchozí dokument již obsahuje placeholder `virtualIp`.
- Stávající `create-default-config` může zůstat jako obrana pro soubor smazaný za běhu služby, ale první instalace ani běžný restart na něm už nesmějí záviset.
- Nynější omezení `createDefaultContracts` pouze na režimy create/reset je nutné odstranit. `buildWizardDocument` musí v edit/repair režimu pracovat aditivně nad existujícím objektem `communicationContracts`, ne jej znovu sestavit od nuly.
